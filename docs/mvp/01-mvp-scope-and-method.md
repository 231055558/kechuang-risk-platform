# MVP 范围与 KCR-2026.08-v1 方法契约

状态：**已冻结，可进入数据模型设计**

冻结日期：2026-08-14

目标演示日期：2026-08-21

机器可读契约：`src/data/methods/kcr-2026.08-v1.json`

## 一句话目标

面向投资机构和金融机构，交付一条可在 3 分钟内完整演示的科创企业风险研判链路：

> 选择企业与评估时点 → 查看客观风险基线 → 下钻风险维度与证据 → 查看风险关系图 → 对比有限情景 → 导出报告 → 生成处置任务

产品不是企业搜索工具，也不承诺替代投资、审计或法律判断；核心价值是把风险结论、
计算过程和来源证据连成可复核的决策链。

## MVP 必须完成

| 编号 | 能力 | 完成标准 |
| --- | --- | --- |
| MVP-01 | 企业与快照 | 可选择寒武纪并明确展示评估日期、数据截止日期和方法版本 |
| MVP-02 | 客观风险基线 | 展示总分、等级和 5 个风险维度，不以缺失数据补零 |
| MVP-03 | 数据质量 | 分开展示证据覆盖率、置信度和数据缺口 |
| MVP-04 | 红旗事件 | 制裁、重大诉讼等红旗单独突出，不被平均分稀释 |
| MVP-05 | 可解释证据链 | 指标和事件可下钻到来源、链接、页码/位置、时间与置信度 |
| MVP-06 | 轻量关系图 | 展示企业、风险维度、事件、专利、供应链和人员之间的关键关系 |
| MVP-07 | 情景对比 | 客观基线保持不变，只允许使用预设或受限权重，并排显示结果差异 |
| MVP-08 | 报告 | 可导出带方法版本、快照时间、证据引用和免责声明的演示报告 |
| MVP-09 | 处置闭环 | 高风险可生成负责人、截止日期和状态明确的行动卡片 |
| MVP-10 | 稳定演示 | 无外网和无实时抓取时，寒武纪黄金样例仍可完整演示 |

寒武纪黄金样例必须复现：总分 `35.6`（中风险）、证据覆盖率 `95%`、置信度
`88.75%`；5 个维度依次为技术 `20.8`、合规 `46.5`、财务融资 `28.5`、
外部环境 `63.75`、人员治理 `17.6667`。

## 指标方法：KCR-2026.08-v1

风险分值统一采用 `0–100`，数值越高表示风险越高。18 个加权指标形成 5 个客观
风险维度，总权重为 100；4 个叙事指标只做主观校验，不参与任何分值计算。

| 维度 | 权重 | 指标 |
| --- | ---: | --- |
| 技术风险 | 25 | T01 专利与知识产权质量代理（4）；T02 核心技术人员/研发人员占比（5）；T03 研发投入强度与趋势（6）；T04 研发/募投里程碑兑现度（5）；T05 重大技术与知识产权事件（5） |
| 合规风险 | 20 | C01 监管处罚强度（5）；C02 交易所问询与披露风险（4）；C03 诉讼与知识产权纠纷（11） |
| 财务与融资风险 | 20 | F01 营业收入增长与波动（6）；F02 无形资产与研发资本化减值（4）；F03 融资成本与期限错配（4）；F04 存货与预付款占用（模型补充项）（6） |
| 外部环境风险 | 20 | E01 关键供应链进口/集中依赖（7）；E02 海外业务暴露（4）；E03 出口管制与制裁暴露（9） |
| 人员与治理风险 | 15 | P01 控制权稀释与稳定性（5）；P02 高管关联风险暴露（4）；P03 关键管理与技术人员稳定性（6） |

叙事校验项：N01 叙事热度基本面背离度、N02 第三方与自身表述偏差、N03 自身
评价一致性/稳定性、N04 概念股标签关联度。它们必须显示为“校验信息”，不得写入
总分或维度分数。

### 冻结的计算语义

- 缺失不等于 0；缺失指标不进入得分分子或分母，并进入数据缺口清单。
- 覆盖率按“已有有效观测的指标权重 ÷ 100”单独计算。
- 置信度与风险分、覆盖率分别展示，不得混成一个数字。
- 每一个进入评分的观测必须绑定可追溯证据。
- 红旗事件单独输出，不能因为其他低风险指标而消失。
- 客观基线使用固定专家权重；用户情景不得覆盖或改写基线。
- 所有输出必须携带方法版本、快照时间和免责声明。

## 数据与证据边界

- MVP 默认使用预先采集并缓存的快照数据，不在演示主链路中同步抓取网页。
- 公开来源优先；天眼查等商业 API 只补关键缺口，并记录调用目的与成本。
- 专利优先进入 MVP，论文暂缓。
- 无法从公开或已授权来源获得的内部研发、客户测试和监管内部数据，明确标为缺失或
  人工补录，不伪造、不推测。
- 原始聊天、会议转写、私密附件、密钥和付费 API 原始响应不得提交到仓库。

## 本期明确不做

- 20–40 分钟的按需实时全网抓取。
- 自建大型数据库、Neo4j 集群或复杂微服务拆分。
- 多用户登录、权限和组织管理。
- 完全自由的指标权重编辑。
- 论文数据管线和复杂新闻情绪模型。
- 把叙事或新闻热度直接计入风险总分。
- 承诺只有律师、监管机构或企业内部才能获得的数据。

## 与现有代码的迁移关系

当前页面仍运行 `KCR-2026.07-v2`：6 个一级类别、17 个二级组、43 个三级指标，
其中技术专项使用 `KTR-2026.07-v1`。它是旧演示壳的数据口径，不再作为新 MVP
方法事实源。

迁移必须遵循以下顺序：

1. 本文件和 `kcr-2026.08-v1.json` 成为新版唯一方法契约。
2. 第 2–5 步建立新版数据模型、导入器、评分引擎和 API；旧版保持可运行。
3. 第 6 步前端整体切换到新版 API 后，才移除旧版 6/17/43 的用户可见文案。
4. 禁止把旧指标 ID 静默解释成新指标 ID；需要兼容时必须使用显式迁移映射。

这样可以避免在后端尚未准备好时破坏现有页面，也避免同一份报告混用两套方法版本。
