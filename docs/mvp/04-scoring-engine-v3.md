实现位置：

## 可直接查看的结果

```bash
npm run score:kcr -- src/data/mvp/cambricon-scoring-input-v3.json
```

终端会显示总分、风险等级、证据覆盖率、置信度、红旗数和五个维度分。若还需要保存
完整审计结果：

```bash
npm run score:kcr -- src/data/mvp/cambricon-scoring-input-v3.json result.json
```

`result.json` 包含每项指标的权重贡献、证据 ID、公式轨迹、缺失项、红旗事件和传播路径。

## 计算规则

客观基线只使用有分数的加权指标：

```text
客观基线 = Σ(风险分 × 固定权重) / Σ(有分数指标的权重)
```

这意味着缺失数据不当作 0 分，也不进入分子或分母。质量指标独立计算：

```text
证据覆盖率 = Σ(固定权重 × 覆盖系数) / 100
置信度     = Σ(固定权重 × 证据置信度) / 100
```

完整、部分、缺失观测的覆盖系数固定为 `1`、`0.75`、`0`。每个非缺失分数必须绑定
直接证据，或写明推断依据的推断证据；只有背景材料不能支撑评分。

风险等级边界固定为：

| 分数范围      | 等级 |
| ------------- | ---- |
| `0 ≤ x < 25`  | 低   |
| `25 ≤ x < 50` | 中   |
| `50 ≤ x < 75` | 高   |
| `75 ≤ x ≤ 100`| 极高 |

红旗事件单独输出，永不覆盖客观基线。传播风险按每条边的“关系强度 × 时间衰减 ×
业务相关度”连续相乘；整条路径系数低于 `0.05` 时不计入，只保留候选值供审计。

## 安全边界

- 指标 ID、所属维度和 100 总权重均以代码常量重新校验，不信任输入合计。
- 风险分必须位于 0–100，覆盖系数、置信度和传播系数必须位于合法范围。
- 缺失数据会显式降级为 `partial` 或 `insufficient-data`；证据覆盖率低于 70% 时要求人工复核。
- 每次计算生成与输入内容绑定的稳定运行标识；生成时间不影响该标识，便于复算比对。
- 评分结果是风险识别和辅助研判，不构成投资、法律、审计或监管意见。

## 对 MVP 的推进

第 3 步解决了“Excel 能否安全进入系统”，本步骤解决了“进入系统后能否得到唯一、可解释、
可复现的风险结论”。后续 API 和页面可以直接消费本引擎结果，不需要在前端重复实现公式。
