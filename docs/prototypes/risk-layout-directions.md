# 风险总览结构原型（待选型）

状态：仅用于本地设计评审，不进入生产构建与正式 PR。

## 要回答的问题

在不改变现有评分、企业、指标、事件和来源数据的前提下，风险总览应该采用哪种信息架构，才能同时具备客户可读性、分析效率和明显的业务动效？

## 启动与切换

```bash
npm run dev
```

- A：`http://127.0.0.1:5173/?variant=A` — 投委会简报
- B：`http://127.0.0.1:5173/?variant=B` — 研究终端
- C：`http://127.0.0.1:5173/?variant=C` — 证据卷宗

页面底部切换器和键盘左右方向键可以切换原型。生产构建不会启用查询参数或显示切换器。

## 三个方向真正不同的地方

| 原型 | 首要任务 | 页面骨架 | 主要交互 |
| --- | --- | --- | --- |
| A 投委会简报 | 快速理解结论 | 左侧风险位置 + 右侧连续研究正文 | 风险驱动联动建议和证据 |
| B 研究终端 | 扫描全部指标 | 五维风险带 + 指标表 + 常驻检查器 | 选择指标行查看数值、公式、来源和处置 |
| C 证据卷宗 | 阅读风险事实 | 风险索引 + 证据时间线 + 研判侧栏 | 选择风险后突出对应事件和建议 |

## 动效评审点

- 企业数据加载完成后，综合分从 0 计算到真实终值。
- 同业位置标记沿风险轴移动到真实排名位置。
- 风险条按照当前企业的真实分数依次展开。
- 选择 Rxx 指标时，相关建议和事件证据同步突出；没有结构化事件时明确显示为空，不补造证据。
- `prefers-reduced-motion` 开启时直接显示终态。
