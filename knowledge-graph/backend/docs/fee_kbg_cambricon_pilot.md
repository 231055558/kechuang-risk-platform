# 寒武纪 FEE-KBG 试点

本试点将论文中的“实体—事件—风险”三级结构适配到现有 R01-R22
风险指标主库。试点范围固定为中科寒武纪科技股份有限公司（688256），
不会修改原始采集、观测、来源、复核决策或历史图谱快照。

## 数据模型

- 实体层：寒武纪、供应商、人员、股东候选、监管机构、法院、行业和概念。
- 事件层：经过日期、标题、来源与置信度校验的具体事件及事件论元。
- 风险层：主题风险事件、R01-R22 二级指标、一级风险类别和辅助预警。
- 证据层：公告、裁判文书、监管文件等来源节点。

## 双知识图谱视图

前端提供两个相互独立的入口：

- **企业主体风险事件传导图谱**：参考论文的实体层—事件层—风险层布局，只展示达到风险事件影响阈值的
  风险主体，形成“风险主体 → 风险事件 → 寒武纪 → 事件主题 → 指标 → 风险类别”的
  加权传导路径。
- **外部主体影响全景图谱**：先展示全部达到主体重要性阈值的供应商、客户、股东和
  高管。风险链必须从该外部主体自身或其关联企业的已核验事件出发，经供应、股权或
  关键人员关系传到寒武纪，再映射至 R01-R22 指标；没有外部事件的主体保持中性。
  寒武纪自身事件、监管机构和法院不再作为该图的风险源。

两个图谱均提供 0.75、0.50 和 0.35 三档阈值。默认使用 0.50，低于阈值的主体
不会进入当前视图，但原始主体和证据仍保留在 SQLite 与完整图谱快照中。

## 主体影响权重

主体影响结果写入 `fee_subject_impacts`。当前模型区分以下口径：

- 监管机构、法院和诉讼当事人：事件严重度 45% + 证据置信度 35% + 关系直接性 20%。
- 供应商：采购占比 45% + 供应链事件严重度 35% + 证据置信度 20%。
- 核心技术人员群体：只由明确的离职、离任和调整事件建立直接影响关系。
- 供应商影响属于“暴露度推演”，不表示供应商已经实际发生事故。

默认 0.50 阈值纳入 11 个高影响风险源：上海证券交易所、美国商务部工业与安全局
（BIS）、北京市海淀区人民法院、梁军、薛兆江、核心技术人员群体、中科可控信息
产业有限公司、深圳市朗华供应链服务有限公司、新思科技有限公司、安谋科技（中国）
有限公司，以及内部风险源“存货与战略备货”。

已识别的股东和高管个体保留为候选主体。由于当前没有取得可以归属于这些个体的
负面事件证据，它们可以进入外部主体全景图，但不会进入风险事件传导链。

主体本身的重要性独立写入 `fee_subject_influences`：供应商和客户使用交易规模、
时效性及证据质量；股东使用持股比例；高管和核心人员使用职务与技术关键性。
主体重要不等于主体存在风险，寒武纪自身事件也不能抬高外部主体的重要性。

外部事件和路径分别写入 `fee_external_subject_events` 与
`fee_external_transmission_paths`。当前公开来源形成四条路径：新思科技对华 EDA
出口限制及后续撤销、安谋科技历史公司治理问题、龙芯中科实体清单事件经董事刘新宇
向寒武纪传导。默认 0.50 阈值显示前三条风险暴露路径；限制撤销属于低权重缓释事件，
在 0.35 扩展视图中与前一事件共同展示演化关系。

派生结果写入 `fee_*` 表，并同时投影为一个普通的
`knowledge_graph_*` 版本化快照。所有事件演化边均由离线模型计算后持久化，
API 不会临时生成“未来事件”。

## 构建与校验

```powershell
Set-Location knowledge-graph/backend
$py = (Get-Command python -ErrorAction Stop).Source

& $py tools\run_fee_kbg_pilot.py --run-id cambricon_fee_kbg_20260826_v1
& $py tools\verify_fee_kbg_pilot.py --run-id cambricon_fee_kbg_20260826_v1
```

也可以运行统一脚本。未启动 Neo4j 时使用 `-SkipNeo4j`：

```powershell
.\tools\refresh_fee_kbg_cambricon.ps1 -RunId cambricon_fee_kbg_20260826_v1 -SkipNeo4j
```

Neo4j 已启动且设置密码后，去掉 `-SkipNeo4j` 即可构建、校验并同步：

```powershell
$env:NEO4J_PASSWORD = Read-Host "Neo4j password"
.\tools\refresh_fee_kbg_cambricon.ps1 -RunId cambricon_fee_kbg_20260826_v1
```

最后运行 `tools\serve_risk_graph_api.py`，访问 `http://127.0.0.1:8765/`。
前端分别读取 `/api/fee-transmission` 与 `/api/subject-panorama`。

没有 Neo4j 密码但需要检查当前 SQLite 快照时，可启动只读预览服务：

```powershell
& $py tools\serve_fee_kbg_preview.py --run-id cambricon_fee_kbg_20260826_v1 --port 8766
```

该服务只用于本机开发与视觉验收，不代替 Neo4j 生产读取链路。

## 演化评分

演化候选必须满足时间严格正向，并至少满足同主题、共享原始指标或文本
相似度门槛之一。评分由时间衰减、主题共享、中文字符 TF-IDF 语义相似度、
事件主体和风险方向五部分组成。每个评分分量、时间间隔和模型版本都保存在
`fee_event_evolution_edges`。该关系表示历史关联演化，不代表因果关系。

## 预警口径

- `E_conservative`：论文四类关系权重下的保守关联指数；缺失关系层按 0 计。
- `E_observed_adjusted`：仅在已有关系层内归一，用于诊断，不能作为全市场排名。
- `E_supply_chain_experimental`：科创企业供应链实验层，不并入论文基线。
- `H_historical`：只按事件的原始 R01-R22 归属计算，不重复计入规则推断指标。
- `W_auxiliary_warning`：保守 E 与 H 的试点组合分，只用于辅助排序。

人员和股东旧记录中存在上游误分类。修复后节点保留 `needs_review=true`，不会
进入正式 E 指数。所有分值都带覆盖率和限制说明，不应解释为违约概率、事实性
经营结论或投资建议。

## 2026-08-27 免费公开源补充

本轮未调用付费接口。上交所官方募集说明书补充了“前五大客户收入占比持续超过
80%”这一已发生的风险披露，并形成两级条件演化：主要客户需求变化可能先导致
收入波动扩大，在回款周期同时延长时，进一步演化为经营现金流压力上升。两级
场景均保存方向、触发条件、概率、期限和递增严重度，不视为已经发生的事实。
